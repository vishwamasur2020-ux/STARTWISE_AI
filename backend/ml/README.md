## Overview

The ML pipeline trains 4 machine learning models to predict startup/business viability:

| Model | Algorithm | Target | Type |
|---|---|---|---|
| Success Model | RandomForestClassifier | `success` (0/1) | Binary Classification |
| Risk Model | DecisionTreeClassifier | `risk_level` (Low/Medium/High) | Multi-class Classification |
| ROI Model | LinearRegression | `roi` (%) | Regression |
| Competition Model | RandomForestClassifier | `competition_level` (Low/Medium/High) | Multi-class Classification |

A **Business Score (0–100)** is calculated from model outputs using a transparent, weighted formula.

**File:** `ml/preprocessing/data_preprocessing.py`

Steps:
1. **Validation** — checks nulls, ranges, duplicates, valid categoricals
2. **Cleaning** — drops duplicates, IQR outlier clipping
3. **Feature/Target separation** — targets excluded from X
4. **Train/Test split** — 80/20, stratified for classifiers

```python
# Numeric: Impute (median) → StandardScaler
# Categorical: Impute (mode) → OneHotEncoder(handle_unknown='ignore')
```

**Critical rule:** The `ColumnTransformer` is fitted **only** on `X_train`, then applied to `X_test`. This prevents data leakage.

## Algorithms & Academic Justification

### Why RandomForest for Success Prediction?

- **Ensemble method** — builds 200 trees, averages predictions (reduces overfitting)
- **Bagging** — each tree trained on random subset of rows AND features
- **`predict_proba()`** — gives calibrated probability (e.g., 84.5% success)
- **Feature importance** built-in — explains which factors drive success
- **Handles imbalanced classes** via `class_weight='balanced'`

### Why DecisionTree for Risk Classification?

- **Interpretability** — tree rules are human-readable (viva-friendly!)
- Example rule: "If `profit_margin < 0` AND `competition = High` → High Risk"
- **Non-parametric** — no assumptions about data distribution
- **Multi-class** — handles Low/Medium/High directly
- Constrained with `max_depth=8` to avoid overfitting

### Why LinearRegression for ROI?

- **ROI is continuous** — regression problem, not classification
- **Interpretable coefficients** — each feature's contribution to ROI is directly readable
- Serves as baseline — if non-linear models don't improve much, simpler is better
- Ridge comparison added to handle multicollinearity

### Why KNN may be used for Franchise Recommendation (Stage 8)?

- KNN finds "nearest" franchises based on distance metrics
- Suitable for recommendation because it returns the most similar items
- No training needed — just distance computation at query time

## Evaluation Metrics

### Classification (Models 1, 2, 4):

| Metric | Definition |
|---|---|
| **Accuracy** | (TP + TN) / Total — overall correctness |
| **Precision** | TP / (TP + FP) — of predicted positives, how many are correct |
| **Recall** | TP / (TP + FN) — of actual positives, how many we found |
| **F1 Score** | 2 × (P × R) / (P + R) — harmonic mean, good for imbalanced data |
| **ROC-AUC** | Area under ROC curve (Success model only) |

### Regression (Model 3 — ROI):

| Metric | Definition |
|---|---|
| **MAE** | Mean Absolute Error — average error in % |
| **RMSE** | Root Mean Squared Error — penalizes large errors |
| **R²** | Coefficient of determination: 1.0 = perfect |

### Why not use Accuracy alone?

Accuracy can be misleading for imbalanced classes. If 80% of records are "success = 1", a model that always predicts success would have 80% accuracy but be useless. F1 score accounts for both Precision and Recall.

## Limitations

1. **Synthetic Data** — Correlations are programmatically designed. Real business outcomes depend on hundreds of unmeasured factors.
2. **Limited feature set** — The model doesn't include macro-economic indicators, credit scores, regulatory environment, etc.
3. **Decision Tree overfitting risk** — Single trees can memorize training data. `max_depth` and `min_samples` constraints mitigate this.
4. **Linear ROI assumption** — ROI relationships may be non-linear in reality. This is an academic simplification.
5. **No temporal data** — The dataset doesn't capture time-series patterns or seasonal effects.

## Viva Reference

### What is Feature Engineering?

Creating new meaningful features from existing raw data. Example: `profit_margin = profit / revenue` captures the business efficiency better than raw profit alone.

### What is Train/Test Split?

Dividing data into a training set (80%) and a test set (20%). The model learns from training data and is evaluated on unseen test data to check real-world performance.

### What is Overfitting?

When a model learns the training data too well (including noise) and performs poorly on new data. Solved by: regularization, max_depth limits, cross-validation, more training data.

### Why Preprocessing is Required?

- Models can't handle text categories directly → OneHotEncoder
- Models are sensitive to scale differences → StandardScaler (e.g., investment ₹1,000,000 vs demand score 7)
- Missing values break most ML algorithms → SimpleImputer
